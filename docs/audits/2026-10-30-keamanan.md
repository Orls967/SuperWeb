## 2. Bagian A — Audit Keamanan Aplikasi Terperinci

### A1. Otorisasi Horizontal (IDOR) & Validasi Parameter Kepemilikan
- **S-01 [P0]**: Pada rute `GET /distribution/{distributor}`, pengguna dengan peran `distributor` diizinkan melihat seluruh faktur AR (`arInvoices`), laporan aging piutang (`agingReport`), scorecard kepatuhan harga, diskon tier, dan surat jaminan bank milik distributor pesaing. Controller tidak memvalidasi `$distributor->owner_user_id === $request->user()->id`.
- **S-02 [P0]**: Pada rute `GET /agency/{agent}`, pengguna dengan peran `agent` dapat melihat buku tahunan (`buildStatement`), komisi multi-tier, akrual royalti, dan riwayat payout milik agen lain tanpa pembatasan kepemilikan.
- **S-03 [P0]**: Pada modul Resto, controller pembelian (`PurchaseController`) dan transfer stok mengizinkan peran `outlet_manager` yang ditugaskan pada Outlet 2 untuk melihat (`resto.purchases.show`) dan membayar utang faktur (`resto.purchases.pay`) untuk Outlet 1. Form pembuatan PO menerima `outlet_id` mentah dari formulir tanpa memvalidasi penugasan staf pada `resto_staff_assignments`.
- **S-04 [P0]**: Pada rute `POST /b2b/escrow/release`, pengguna dengan peran pelanggan `b2b_buyer` dapat mengirimkan ID escrow arbitrer dan memicu pencairan dana buku besar tanpa verifikasi bahwa pemanggil adalah pembeli sah dari escrow tersebut.
- **S-05 [P0]**: Pada rute `POST /agri/payout/settle`, pengguna dengan peran `farmer` dapat mengeksekusi penyelesaian kliring buku besar (`SettleFarmerPayoutNetOfInputLoanViaLedgerAction`) secara langsung.
- **S-06 [P1]**: Pada rute `POST /bookings`, pelanggan dapat mengirimkan parameter `vehicle_id` milik pengguna lain. Controller menyematkan kendaraan tersebut ke reservasi baru tanpa memverifikasi kepemilikan kendaraan.

### A2. Otorisasi Vertikal & Sampling Rute Tulis
Sebanyak 40 rute tulis disampel secara acak dengan seed `20261030`. Hasil evaluasi menunjukkan bahwa sebagian besar rute administratif terproteksi middleware `role:admin,...`. Namun rute operasional pada modul B2B dan Agri membuka rute eksekusi finansial kepada peran berprivilese rendah (`b2b_buyer`, `farmer`).

### A3. Mass Assignment
Pemeriksaan menyeluruh menunjukkan kepatuhan terhadap ArchScan A10:
```bash
git grep -n "\$guarded = \[\]" modules app
# Exit code: 0 (0 model matches di modules/app)
```
Model `User` mendefinisikan atribut sensitif `role` di dalam `$fillable`, namun aksi registrasi `RegisteredUserController@store` mengunci nilai peran secara hardcoded (`role => customer`), dan pembaruan profil `ProfileUpdateRequest` hanya mengizinkan `name` dan `email`.

### A4. Injeksi SQL
Pemeriksaan fungsi penyusun query mentah (`DB::raw`, `whereRaw`, `selectRaw`, `orderByRaw`, `DB::statement`):
```bash
git grep -nE "whereRaw\(|selectRaw\(|orderByRaw\(|havingRaw\(|DB::statement\(|DB::select\(" modules app
```
Seluruh input pengguna yang dipetakan ke dalam query mentah pada layer controller telah menggunakan prepared statement binding (`?`). Sebanyak 11 kemunculan `DB::raw("balance + {$var}")` pada layer aplikasi Integration beroperasi pada variabel integer internal yang telah divalidasi tipe datanya.

### A5. Cross-Site Scripting (XSS)
- **S-13 [P1]**: Ditemukan injeksi HTML/XSS akibat penggunaan tag `{!! session('success') !!}` tanpa escaping pada:
  - `modules/Vending/resources/views/vending/markdowns.blade.php:25`
  - `modules/Venue/resources/views/venue/bottle_surge.blade.php:25`
  Jika pesan notifikasi menyematkan string input pengguna mentah, skrip JavaScript berbahaya akan dieksekusi di peramban korban.

### A6. Keamanan Unggah Berkas
Implementasi `DocumentStoreService` memblokir ekstensi berbahaya (`php`, `phtml`, `phar`, `exe`, `sh`, `svg`) melalui `DISALLOWED_EXTENSIONS`. Berkas disimpan pada disk privat `local` dengan nama acak berbasis UUID (`documents/Y/m/{uuid}.ext`). Akses unduhan melalui `storage.local.upload` diwajibkan menggunakan URL bertanda tangan kriptografis (`URL::temporarySignedRoute`).

### A7. Server-Side Request Forgery (SSRF)
- **S-07 [P1]**: Pada modul Logistics (`DispatchWebhookAction@attemptDelivery`), URL webhook mitra dieksekusi langsung melalui `Http::post($endpoint->url)` tanpa validasi alamat IP privat atau metadata cloud (`169.254.169.254`, `127.0.0.1`, RFC 1918), berbeda dengan implementasi aman di `Modules\Core\Application\Services\OutboxBusService::isSafeWebhookUrl`.

### A8. Autentikasi, Sesi, dan Brute-Force Rate Limiting
- **S-10 [P1]**: Rute `POST /login`, `POST /forgot-password`, dan `POST /reset-password` di `routes/auth.php` tidak dilindungi oleh route-level rate limiting middleware. Meskipun `LoginRequest` memiliki batasan internal 5 percobaan, mekanisme tersebut menghasilkan kode respon 422 redirect alih-alih HTTP 429 Too Many Requests standar.

### A9. Perlindungan CSRF
Seluruh rute mutasi state (POST/PUT/PATCH/DELETE) dilindungi oleh token CSRF melalui grup middleware `web`. Tidak ditemukan rute GET operasional yang mengubah status data keuangan atau status operasional entitas.

### A10. Kriptografi & Rahasia Ter-Commit
Pemindaian riwayat git dan kode sumber:
```bash
git grep -nE "(sk_live|AKIA|-----BEGIN (RSA |EC )?PRIVATE KEY|password\s*=\s*['\"][^'\"]{6,})" -- ':!*.lock' ':!tests' ':!docker-compose.prod.yml'
# Exit code: 0 (Tidak ada API key AWS atau Private Key tersimpan di kode aplikasi)
```
- **S-12 [P2]**: Ditemukan kata sandi basis data default hardcoded di dalam berkas konfigurasi orkestrasi `docker-compose.prod.yml` (`superweb_db_secret`, `superweb_root_secret`, `superweb_redis_secret`).

### A11. Paparan Data Sensitif (PII)
- **S-08 [P1]**: Model `Party` (`pty_parties`), `Employee` (`hcm_employees`), dan `Tenant` (`mall_tenants`) menggunakan casting `encrypted` untuk kolom `nik` dan `npwp`, namun tidak mendefinisikan properti `$hidden`. Saat model diserialisasi ke array atau respon JSON API, nilai NIK dan NPWP terdekripsi menjadi teks terang (plaintext).

### A12. Header Keamanan Web
- **S-09 [P1]**: Respon HTTP web aplikasi tidak menyertakan header keamanan esensial (`Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security`).
